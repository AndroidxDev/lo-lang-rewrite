Язык lo полностью отказывается от ключевых слов, двоеточий и значимых отступов. Вся грамматика строится на правиле четырёх скобок, где каждый тип скобок отвечает ровно за одну сущность, поэтому парсер языка (Recursive Descent + Pratt Parser) пишется за пару сотен строк кода, а сам код можно форматировать как угодно — хоть в одну строку.
1. Архитектура четырёх скобок
В lo нет зарезервированных слов (if, for, fn, let, return, struct, import). Их заменяют 4 вида скобок:
 * [ ... ] — Данные и Типы: массивы, структуры, перечисления и аннотации типов. Внутри них никогда нет исполняемого кода.
 * { ... } — Логика и Блоки: функции, ветвления, тела циклов и потоков. Всё внутри фигурных скобок — отложенное вычисление, возвращающее последнее выражение.
 * ( ... ) — Вычисление и Аргументы: вызов функций, передача параметров, условия и математическая группировка.
 * < ... > — Внешний мир и Мета-уровень: импорт модулей, директивы компилятора и вызовы C ABI (FFI).
Разделителями элементов внутри любых скобок служат запятая , или перевод строки \n (они полностью взаимозаменяемы, отступы игнорируются).
2. Лексика и примитивные типы
# Однострочный комментарий
#[ Многострочный (допускает вложенность #[ ... ]#) комментарий ]#

Примитивные типы (выводятся автоматически, пишутся только при FFI или уточнении):
 * Целые числа: i8, i16, i32, i64 (по умолчанию), u8, u16, u32, u64, usz.
 * Дробные числа: f32, f64 (по умолчанию).
 * Логический тип: bool (литералы 1b — истина, 0b — ложь, чтобы не вводить текстовые ключевые слова).
 * Строки и символы: str (UTF-8 срез в двойных кавычках "Привет"), char (в одинарных 'a'). Внутри "..." работает интерполяция через {выражение}.
 * Пустой тип (Unit): [].
3. Переменные и управление памятью
Язык различает создание константы, создание изменяемой переменной и мутацию, что исключает случайное затенение (shadowing) и гонки данных:
# 1. Неизменяемая привязка (=)
pi = 3.14159
msg = "Версия {pi}"

# 2. Публичный экспорт из модуля (префикс +)
+max_users = 1000

# 3. Изменяемая переменная (~= разрешена только внутри функций {})
score ~= 0

# 4. Мутация существующей переменной (<-)
score <- score + 10
score +<- 5          # Сокращенная форма (также -<-, *<-, /<-)

4. Единая система данных [ ... ]
Квадратные скобки заменяют списки, кортежи, структуры, словари и типы данных. Компилятор статически определяет, во что превратить [ ... ] в машинном коде:
# 1. Однородный массив (в памяти — плоский C-массив)
nums = [10, 20, 30, 40]
first = nums[0]              # Индексация с проверкой границ

# 2. Массив фиксированного размера с заполнением (1024 нуля типа u8)
buffer = [0 [u8] .. 1024]

# 3. Структура (если элементы заданы через =)
# Компилируется в плоскую C-структуру в стеке без хеш-таблиц
user = [
  name = "Alex"
  hp = 100
  pos = [x = 12.5, y = -4.0]
]
name = user.name             # Доступ к полю через точку

# 4. Обновление структуры (копирование со спредом ..)
# Благодаря алгоритму Perceus, если старый user больше не нужен,
# компилятор изменит память "на месте" без аллокаций
hit_user = [..user, hp = user.hp - 25]

# 5. Объявление типа (схемы) — идентификатор с заглавной буквы
# Значения по умолчанию одновременно задают тип поля
Player = [
  name = ""                  # Поле типа str, по умолчанию ""
  hp = 100                   # Поле типа i64, по умолчанию 100
  team [u8]                  # Поле типа u8 без значения по умолчанию
]

p1 = Player[name = "Max", team = 1]

# 6. Алгебраические типы / Перечисления (разделитель | внутри [])
State = [
  Idle
  Run(f64)
  Attack[target = i64, dmg = i64]
]

5. Функции и блоки ( ... ) { ... }
Функция — это обычное значение, состоящее из опциональных параметров ( ... ) и тела { ... }. Последнее выражение внутри { ... } возвращается автоматически.
# Обычная функция (типы аргументов выводятся сами)
add = (a, b) { a + b }

# Явная аннотация типов через [Тип] (нужна только для границ API/FFI)
mul = (a [i32], b [i32]) [i32] { a * b }

# Функция без аргументов
get_id = { 42 }

# Вызов функции
res = add(10, 20)
id = get_id()

# Множественный возврат и деструктуризация через []
swap = (a, b) { [b, a] }
[x, y] = swap(1, 2)

# Досрочный выход из блока/функции — оператор ^ (каретка)
safe_div = (a, b) {
  ? (b == 0) { ^ 0 }
  a / b
}

# Рекурсия без имени — символ $ всегда ссылается на текущую функцию {}
fact = (n) {
  ? (n <= 1) { ^ 1 }
  n * $(n - 1)
}

6. Условия и сопоставление с образцом (?)
Оператор ? заменяет if, else, switch и match. Символ _ означает «любое значение» (ветка по умолчанию / else).
# 1. Тернарная / условная форма: ? (условие) { то } { иначе }
status = ? (hp > 0) { "жив" } { "мертв" }

# 2. Мульти-ветвление (замена if / else if / else)
grade = (pts) {
  ? {
    (pts >= 90) { "A" }
    (pts >= 75) { "B" }
    (pts >= 60) { "C" }
    _           { "F" }
  }
}

# 3. Pattern Matching (сопоставление структуры или перечисления)
handle = (state) {
  ? (state) {
    Idle                  { stop() }
    Run(speed)            { move(speed) }
    Attack[dmg = d, ..]   { apply_damage(d) }
    _                     { reset() }
  }
}

7. Безопасная обработка ошибок (?, ??, ?!)
В lo нет null и исключений. Любая функция, способная завершиться неудачей, возвращает неявный объединенный тип [Значение | Err[code = i32, msg = str]].
# 1. Оператор ?? — значение по умолчанию при ошибке или пустоте
port = parse_int(env("PORT")) ?? 8080

# 2. Оператор ?! — перехват ошибки с блоком обработки
# Внутри блока символ @ содержит сам объект ошибки
config = read_file("app.cfg") ?! {
  print("Ошибка чтения: {@.msg}")
  ^ "default_config"
}

# 3. Постфиксный ? — проброс ошибки наверх (как в Rust)
load_user = (id) {
  raw = db_query(id)?        # Если ошибка — мгновенный возврат её из load_user
  parse_user(raw)?
}

8. Циклы, потоки и многопоточность (@, ~>, ~>>)
Для императивных циклов используется символ @, а для функциональных цепочек (которые компилятор сливает в один цикл через loop fusion) — стрелка ~>.
# 1. Безусловный цикл и цикл с условием
# ! — прервать цикл (break), ~ — следующая итерация (continue)
i ~= 0
@ (i < 100) {
  i +<- 1
  ? (i == 50) { ~ }          # continue
  ? (i > 80)  { ! }          # break
}

# 2. Итерация по диапазону или массиву: внутри {} символ @ — текущий элемент
# Диапазоны: 0..10 (не включая 10), 0..=10 (включая 10)
0..5 ~> { print("Шаг {@}") }

# 3. Конвейеры данных (Map -> Filter -> Fold)
total = 1..=100
  ~> { @ * 2 }               # Умножить каждый элемент на 2 (Map)
  ~> ? { @ > 50 }            # Оставить только больше 50 (Filter)
  ~> (sum = 0) { sum + @ }   # Свернуть в сумму с начальным аккумулятором 0 (Fold)

# 4. Безопасная параллельность на всех ядрах CPU (~>>)
# Так как внутри {} запрещено менять внешние переменные, гонок данных быть не может
rendered_frames = raw_frames ~>> { render_shader(@) }

9. Модули и FFI < ... >
Угловые скобки изолируют взаимодействие с операционной системой, внешними файлами и языком C:
# Импорт локального файла или стандартной библиотеки
math = <"std/math">
net  = <"./network.lo">

# Прямой биндинг функции из стандартной библиотеки C (Zero-overhead FFI)
c_puts = <"c" "puts" (str) [i32]>
c_sqrt = <"c" "sqrt" (f64) [f64]>

c_puts("Вызов напрямую в libc!")

| 2 | - ! $ @ | Унарный минус, логическое НЕ, рекурсия, элемент |
| 3 | * / % | Умножение, деление, остаток |

11. Полная формальная грамматика (EBNF) для реализации парсера
Эту грамматику можно напрямую перенести в генератор парсеров (pest, tree-sitter, ANTLR) или реализовать вручную методом рекурсивного спуска:
Program        = { Statement Sep } ;
Sep            = ( "," | "\n" | ";" )+ ;

Statement      = ExportBind | ImmutableBind | MutableBind | Mutation | ControlStmt | Expr ;
ExportBind     = "+" Ident "=" Expr ;
ImmutableBind  = ( Ident | ArrayPat ) "=" Expr ;
MutableBind    = Ident "~=" Expr ;
Mutation       = LValue ( "<-" | "+<-" | "-<-" | "*<-" | "/<-" ) Expr ;
LValue         = Ident { "." Ident | "[" Expr "]" } ;

ControlStmt    = "^" [ Expr ] | "!" | "~" ;

Expr           = PipeExpr ;
PipeExpr       = FallbackExpr { ( "~>" | "~>>" ) PipeStage } ;
PipeStage      = ["?"] [ "(" Ident "=" Expr ")" ] Block | Expr ;

FallbackExpr   = LogicExpr [ ( "??" Expr ) | ( "?!" Block ) ] ;
LogicExpr      = CompExpr { ( "&" | "|" ) CompExpr } ;
CompExpr       = RangeExpr [ ( "==" | "!=" | "<" | ">" | "<=" | ">=" ) RangeExpr ] ;
RangeExpr      = AddExpr [ ( ".." | "..=" ) AddExpr ] ;
AddExpr        = MulExpr { ( "+" | "-" ) MulExpr } ;
MulExpr        = UnaryExpr { ( "*" | "/" | "%" ) UnaryExpr } ;
UnaryExpr      = [ "-" | "!" ] PostfixExpr ;

PostfixExpr    = PrimaryExpr { "." Ident | "[" Expr "]" | "(" [ ArgList ] ")" | "?" } ;
ArgList        = Expr { Sep Expr } ;

PrimaryExpr    = Literal | Ident | "@" | "$"
               | DataBracket | FuncExpr | CondExpr | LoopExpr | MetaBracket | "(" Expr ")" ;

(* 1. Скобки данных [ ... ] *)
DataBracket    = "[" [ DataBody ] "]" ;
DataBody       = ".." Expr { Sep FieldOrExpr }
               | VariantList
               | FieldOrExpr { Sep FieldOrExpr } ;
FieldOrExpr    = Ident [ TypeTag ] [ "=" Expr ] | Expr [ TypeTag ] [ ".." Expr ] ;
VariantList    = Variant { "|" Variant } ;
Variant        = TypeIdent [ "(" TypeList ")" | DataBracket ] ;
TypeTag        = "[" TypeIdent "]" ;
ArrayPat       = "[" Ident { Sep Ident } "]" ;

(* 2. Скобки логики { ... } и функций ( ... ) { ... } *)
FuncExpr       = [ "(" [ ParamList ] ")" ] [ TypeTag ] Block ;
ParamList      = Param { Sep Param } ;
Param          = Ident [ TypeTag ] [ "=" Expr ] ;
Block          = "{" { Statement Sep } "}" ;

(* 3. Условия ? и циклы @ *)
CondExpr       = "?" ( "(" Expr ")" Block [ Block ] | [ "(" Expr ")" ] "{" { MatchArm Sep } "}" ) ;
MatchArm       = ( Pattern | "(" Expr ")" | "_" ) Block ;
Pattern        = Literal | Ident | TypeIdent [ "(" Ident ")" | DataBracket ] ;
LoopExpr       = "@" [ "(" Expr ")" ] Block ;

(* 4. Мета-скобки < ... > *)
MetaBracket    = "<" StringLit [ StringLit "(" [ TypeList ] ")" TypeTag ] ">" ;
TypeList       = TypeIdent { Sep TypeIdent } ;

(* Лексемы *)
Ident          = ( "a".."z" | "_" ) { "a".."z" | "A".."Z" | "0".."9" | "_" } ;
TypeIdent      = ( "A".."Z" ) { "a".."z" | "A".."Z" | "0".."9" } | "i8"|"i16"|"i32"|"i64"|"u8"|"u16"|"u32"|"u64"|"f32"|"f64"|"bool"|"str"|"char" ;
Literal        = NumberLit | StringLit | "1b" | "0b" ;

12. Пример полноценной программы на lo
math = <"std/math">
c_puts = <"c" "puts" (str) [i32]>

# Объявление структуры с типами по умолчанию
Particle = [id = 0, x = 0.0, y = 0.0, active = 1b]

# Функция обновления координаты частицы
step = (p) {
  ? (p.active) {
    [..p, x = p.x + 1.5, y = math.sin(p.x)]
  } {
    p
  }
}

# Точка входа (экспортируемая функция main)
+main = {
  # Генерируем 1000 частиц через поток
  world = 1..=1000 ~> {
    Particle[id = @, x = @ * 0.1, y = 0.0, active = (@ % 2 == 0)]
  }

  # Параллельно обсчитываем физику на всех ядрах, фильтруем активные и считаем сумму X
  total_x = world
    ~>> { step(@) }
    ~> ? { @.active }
    ~> (acc = 0.0) { acc + @.x }

  c_puts("Сумма координат активных частиц = {total_x}")
}

Полная спецификация языка lo (версия 1.0) превращает его в законченный промышленный инструмент. Сохраняя главный принцип — ноль текстовых ключевых слов, ноль двоеточий и правило четырёх скобок — язык получает строгий null-чекер в стиле Kotlin, полноценные цепочки if / else if / else, структурный перехват ошибок try / catch / finally, продвинутую логику return (включая локальные, множественные и генераторные возвраты), интерфейсы, дженерики, словари, срезы и асинхронность.
1. Null-безопасность в стиле Kotlin
В lo все типы по умолчанию строго непустые (non-null). Попытка записать пустоту в обычную переменную не скомпилируется. Для работы с отсутствующими значениями используется символ тильды ~ (литерал null) и вопросительный знак ?.
# 1. Непустой и Nullable типы
name [str]  = "Alex"        # Обычный тип: НИКОГДА не может быть пустым
nick [str?] = ~             # Тип с ? на конце может хранить ~ (null)

# 2. Безопасный вызов ?. / ?[] / ?() (Safe Call)
# Если любой элемент цепочки равен ~, всё выражение вернет ~ без падения
city_len = user?.address?.city?.len
first_item = list?[0]
result = callback?(42)

# 3. Оператор Элвиса ?? (Elvis Operator)
# Возвращает левую часть, если она не ~ (и не ошибка), иначе правую
display_name = nick ?? "Гость"

# Элвис с мгновенным выходом из функции (как в Kotlin: val u = user ?: return)
valid_user = get_user(id) ?? ^ ~

# 4. Безопасный конвейер ?~> (аналог ?.let { ... } в Kotlin)
# Блок выполнится ТОЛЬКО если значение не равно ~. Внутри блока @ — распакованное значение
nick ?~> {
  print("Никнейм существует: {@}")
}

# 5. Принудительная распаковка !! (Not-null assertion)
# Превращает [T?] в [T]. Если там ~, выбрасывает контролируемую ошибку
len = nick!!.len

# 6. Безопасное приведение типов ?[Тип] (аналог as? в Kotlin)
# Если entity не является Admin, вернет ~ вместо падения
admin = entity?[Admin]
admin_name = entity?[Admin]?.name ?? "Не админ"

# 7. Умное приведение (Smart Cast)
# После проверки на != ~ компилятор автоматически меняет тип [str?] на [str]
? (nick != ~) {
  print(nick.len)           # ?. больше не нужен, компилятор знает, что nick не пуст
}

2. Полная логика if / else if / else и match
Оператор ? разделяет проверку логических условий в круглых скобках ( ... ) и сопоставление с образцом в квадратных скобках [ ... ]. Это делает грамматику однозначной.
# 1. Одиночный if
? (hp <= 0) {
  die()
}

# 2. Полная цепочка if / else if / else
# Каждая следующая пара (условие) { блок } — это else if.
# Финальный блок { ... } без условия — это else.
rank = ? (score >= 90) {
  "Мастер"
} (score >= 70) {
  "Эксперт"
} (score >= 50) {
  "Ученик"
} {
  "Новичок"
}

# 3. Короткий однострочный тернарный if / else
label = ? (is_online) { "В сети" } { "Офлайн" }

# 4. Глубокий Pattern Matching (switch / match) через квадратные скобки ? [значение]
# Поддерживает деструктуризацию, диапазоны и дополнительные условия (guards) в ()
? [event] {
  Click[x = 0, y = 0]          { print("Клик в начало координат") }
  Click[x, y] (x > 100)        { print("Клик справа: {x}, {y}") }
  KeyPress('q' | 'Q')          { exit() }
  Wait(1..=10)                 { print("Короткая пауза") }
  ~                            { print("Событие пустое (null)") }
  _                            { print("Другое событие") }
}

3. Полная логика возврата (return, метки и yield)
Любой блок { ... } по умолчанию возвращает свое последнее выражение. Для досрочного или нелокального управления выходом используется семейство операторов каретки ^.
# 1. Неявный возврат (последнее выражение функции)
square = (x) { x * x }

# 2. Явный ранний возврат из функции (^ значение) или пустой возврат (^)
process = (x [i64?]) {
  ? (x == ~) { ^ }              # Выход без значения (возвращает пустой тип [])
  ? (x < 0)  { ^ 0 }            # Досрочный возврат 0
  x * 10
}

# 3. Условный возврат-предохранитель (?^) — замена шаблонному if (...) return
# Если условие слева истинно, функция мгновенно возвращает значение справа
divide = (a, b) {
  (b == 0) ?^ 0.0
  a / b
}

# 4. Множественный возврат и распаковка
min_max = (arr [i64..]) {
  (arr.len == 0) ?^ [0, 0, 0b]
  [arr[0], arr[arr.len - 1], 1b]
}
[first, last, ok] = min_max([10, 20, 30])

# 5. Локальный возврат из лямбды/потока (^@) vs возврат из внешней функции (^)
# Как в Kotlin: обычная ^ выходит из всей функции, а ^@ — только из текущей итерации {}
find_and_transform = (items [i64..]) {
  cleaned = items ~> {
    ? (@ == 999) { ^ [] }       # ^ выйдет из всей функции find_and_transform!
    ? (@ < 0)    { ^@ 0 }       # ^@ вернет 0 только для текущего шага конвейера ~>
    @ * 2
  }
  cleaned
}

# 6. Возврат по именованной метке (#метка и ^#метка)
calc = (matrix) {
  result = #search {
    matrix ~> (row) {
      row ~> (cell) {
        ? (cell == -1) { ^#search 0 }   # Мгновенный выход из блока #search со значением 0
      }
    }
    100
  }
  result
}

# 7. Генераторы (^~ аналог yield в Python)
# Функция с ^~ лениво отдает элементы по одному без выделения памяти под массив
fibonacci = (limit) {
  [a, b] ~= [0, 1]
  @ (a < limit) {
    ^~ a                        # Отдать текущее число в поток и приостановить функцию
    [a, b] <- [b, a + b]
  }
}

# Чтение генератора через стандартный конвейер
fibonacci(1000) ~> { print(@) }

4. Исключения и ресурсы: try / catch / finally и defer
В lo ошибки — это строгие значения, но для удобства работы с внешними системами предусмотрен полноценный блочный синтаксис try / catch / finally без единого ключевого слова:
 * !{ ... } — блок try (защищенная зона выполнения).
 * ?! [ТипОшибки] { ... } или ?! (e) { ... } — блоки catch (перехват по типу или общий перехват).
 * ?> { ... } — блок finally (выполняется всегда при выходе из !{}, даже если внутри сработал ^ или неперехваченная ошибка).
 * !^ выражение — оператор throw / raise (выброс ошибки).
 * ~{ ... } — оператор defer (отложенное выполнение при выходе из текущей функции).
 * ?!{ ... } — оператор errdefer (выполняется при выходе из функции только в случае ошибки).
# Определение собственных типов ошибок
NetErr  = [code = 500, url = ""]
AuthErr = [reason = ""]

fetch_data = (url [str], token [str?]) {
  # Отложенная очистка (defer) — сработает автоматически в самом конце функции
  conn = open_socket(url)
  ~{ close_socket(conn) }

  # Выброс ошибки (throw), если токена нет
  (token == ~) ?^ !^ AuthErr[reason = "Токен отсутствует"]

  # Полная конструкция try / catch / finally
  data = !{
    raw = conn.read()?                  # ? пробрасывает ошибку в блок ?!
    ? (raw.len == 0) {
      !^ NetErr[code = 204, url = url]  # Явный throw ошибки
    }
    parse_json(raw)?
  } ?! [AuthErr(e)] {                   # Catch конкретного типа AuthErr
    log("Ошибка доступа: {e.reason}")
    DefaultPayload[]
  } ?! [NetErr[code = 404, ..]] {       # Catch по конкретному коду внутри ошибки
    log("Страница не найдена")
    DefaultPayload[]
  } ?! (any_err) {                      # Общий Catch для всех остальных ошибок
    log("Сбой: {any_err}")
    DefaultPayload[]
  } ?> {                                # Блок finally — гарантированная финализация
    metrics.record_attempt(url)
  }

  data
}

5. Коллекции: Массивы, Срезы, Словари (Map) и Множества (Set)
Все коллекции создаются внутри квадратных скобок [ ... ], но различаются внутренним оператором:
# 1. Динамический массив [Тип..]
list = [10, 20, 30, 40, 50]

# 2. Срезы (Slices) — мгновенные представления без копирования памяти
mid  = list[1..4]             # [20, 30, 40]
head = list[..2]              # [10, 20]
tail = list[3..]              # [40, 50]

# 3. Структура (статические ключи через =, компилируется в C-struct)
point = [x = 10.0, y = 20.0]

# 4. Словарь / HashMap (динамические ключи через =>, тип [Ключ => Значение])
prices = [
  "apple"  => 120
  "banana" => 80
  "orange" => 150
]

# Чтение из словаря всегда возвращает Nullable-тип [i64?], защищая от отсутствия ключа!
apple_price = prices["apple"] ?? 0

# Добавление/обновление ключа в изменяемом словаре
cart ~= ["apple" => 1]
cart["banana"] <- 3

# 5. Множество / HashSet (префикс %, тип [%Тип])
tags = [% "rust", "lua", "lo"]
has_lo = tags.has("lo")       # 1b (true)

6. ООП без классов: Методы, Интерфейсы и Дженерики
Вместо сложных иерархий наследования lo использует привязку методов к типам, структурные интерфейсы и обобщения (Generics) в угловых скобках. Внутри любого метода символ @ указывает на текущий экземпляр объекта (аналог self или this).
# 1. Объявление структуры
Vec2 = [x = 0.0, y = 0.0]

# 2. Привязка чистых методов (@ — это сам объект self)
Vec2.length = {
  math.sqrt(@.x * @.x + @.y * @.y)
}

Vec2.add = (other [Vec2]) [Vec2] {
  Vec2[x = @.x + other.x, y = @.y + other.y]
}

# 3. Мутирующий метод (суффикс ! в имени разрешает менять поля @ через <-)
Vec2.scale! = (factor [f64]) {
  @.x *<- factor
  @.y *<- factor
}

# 4. Интерфейсы (Трейты) — структура, поля которой являются сигнатурами функций
# Любой тип, имеющий такие методы, автоматически реализует интерфейс (утиная статика)
Serializable = [
  to_bytes = () [u8..]
]

# 5. Дженерики (Обобщенное программирование через мета-скобки < ... >)
# Обобщенный контейнер
Cache = <K, V> [
  store [K => V]
  max_size = 100
]

# Обобщенная функция с ограничением интерфейса <T [Интерфейс]>
save_all = <T [Serializable]> (items [T..]) {
  items ~> { write_disk(@.to_bytes()) }
}

7. Циклы, Асинхронность (async/await) и Каналы
Императивные циклы управляются символом @, а конкурентность встроена на уровне операторов потока без раскрашивания функций ключевыми словами async и await.
# 1. Циклы @ с управлением !@ (break) и ~@ (continue)
i ~= 0
@ (i < 100) {
  i +<- 1
  ? (i % 2 == 0) { ~@ }       # ~@ — перейти к следующей итерации (continue)
  ? (i > 75)     { !@ }       # !@ — прервать цикл (break)
}

# Цикл с возвратом значения (break со значением!)
found = @ (item <- list) {
  ? (item.id == 42) { !@ item }
} ?? DefaultItem[]

# 2. Асинхронные задачи (зеленые потоки) ~>{ ... } и ожидание <~ (await)
# ~>{ ... } запускает блок асинхронно и возвращает дескриптор задачи [~Тип]
task1 = ~>{ download_file("https://site.com/a.zip") }
task2 = ~>{ download_file("https://site.com/b.zip") }

# Оператор <~ дожидается завершения задачи (аналог await)
[file_a, file_b] = [<~ task1, <~ task2]

# 3. Типизированные каналы для общения между потоками
ch = [~i64]()                 # Создание канала для передачи i64

~>{
  1..=5 ~> { ch <~ (@ * 10) } # Оператор <~ справа отправляет данные в канал
  ch.close()
}

# Чтение из канала до его закрытия
@ (msg <- <~ ch) {
  print("Получено: {msg}")
}

8. Побитовые операции и Метапрограммирование (comptime)
Чтобы побитовые операторы никогда не конфликтовали с логическими и со скобками, перед ними ставится точка. А угловые скобки вокруг фигурных <{ ... }> заставляют код выполниться во время компиляции (как comptime в Zig), вшивая готовый результат в бинарный файл.
# 1. Побитовые операции (с точкой)
mask   = 0xFF .& flags        # Побитовое И (AND)
merged = a .| b               # Побитовое ИЛИ (OR)
toggled = a .^ b              # Побитовое исключающее ИЛИ (XOR)
inv    = .~mask               # Побитовая инверсия (NOT)
shifted = 1 .<< 8             # Сдвиг влево (256)
hi_byte = val .>> 24          # Сдвиг вправо

# 2. Вычисление на этапе компиляции <{ ... }> (Zero-cost metaprogramming)
# Таблица синусов рассчитается компилятором при сборке и ляжет в ПЗУ как константа
sin_table = <{
  0..360 ~> { math.sin(@ * 3.14159 / 180.0) }
}>

10. Полная формальная грамматика языка (EBNF)
Данная спецификация покрывает 100% синтаксиса lo v1.0 и готова для прямой загрузки в генератор парсеров или написания компилятора:
Program        = { TopStmt Sep } ;
Sep            = ( "," | "\n" | ";" )+ ;

TopStmt        = [ "+" ] Ident "=" ( TypeDef | Expr ) | MethodDef | Statement ;
TypeDef        = [ GenericParams ] DataBracket ;
MethodDef      = TypeIdent "." Ident [ "!" ] "=" [ GenericParams ] FuncExpr ;
GenericParams  = "<" GenericParam { Sep GenericParam } ">" ;
GenericParam   = TypeIdent [ TypeTag ] ;

Statement      = BindStmt | MutateStmt | DeferStmt | FlowStmt | Expr ;
BindStmt       = ( Ident [ TypeTag ] | DestructPat ) ( "=" | "~=" ) Expr ;
DestructPat    = "[" Ident { Sep Ident } "]" ;
MutateStmt     = LValue ( "<-" | "+<-" | "-<-" | "*<-" | "/<-" ) Expr ;
LValue         = PostfixExpr ;

DeferStmt      = ( "~{" | "?!{" ) { Statement Sep } "}" ;
FlowStmt       = ( "^" | "^@" | "^~" | "!^" ) [ Expr ]
               | "^#" Ident [ Expr ]
               | "!@" [ Expr ] | "!#" Ident [ Expr ]
               | "~@" | "~#" Ident ;

Expr           = GuardExpr ;
GuardExpr      =AsyncSendExpr [ "?^" Expr ] ;
AsyncSendExpr  = PipeExpr [ "<~" Expr ] ;
PipeExpr       = ElvisExpr { ( "~>" | "~>>" | "?~>" ) PipeStage } ;
PipeStage      = [ "?" ] [ "(" Ident [ "=" Expr ] ")" ] Block | Expr ;

ElvisExpr      = OrExpr { "??" ( FlowStmt | OrExpr ) } ;
OrExpr         = AndExpr { "|" AndExpr } ;
AndExpr        = BitOrExpr { "&" BitOrExpr } ;
BitOrExpr      = BitXorExpr { ".|" BitXorExpr } ;
BitXorExpr     = BitAndExpr { ".^" BitXorExpr } ;
BitAndExpr     = CompExpr { ".&" CompExpr } ;
CompExpr       = RangeExpr [ ( "==" | "!=" | "<" | ">" | "<=" | ">=" ) RangeExpr ] ;
RangeExpr      = ShiftExpr [ ( ".." | "..=" ) [ ShiftExpr ] ] ;
ShiftExpr      = AddExpr { ( ".<<" | ".>>" ) AddExpr } ;
AddExpr        = MulExpr { ( "+" | "-" ) MulExpr } ;
MulExpr        = UnaryExpr { ( "*" | "/" | "%" ) UnaryExpr } ;

UnaryExpr      = [ "-" | "!" | ".~" | "<~" ] PostfixExpr ;
PostfixExpr    = PrimaryExpr { PostfixOp } ;
PostfixOp      = "." Ident
               | "?." Ident
               | "[" [ Expr ] [ ( ".." | "..=" ) [ Expr ] ] "]"
               | "?[" Expr "]"
               | "(" [ ArgList ] ")"
               | "?(" [ ArgList ] ")"
               | "<" TypeList ">"
               | "?[" TypeSpec "]"
               | "[" TypeSpec "]"
               | "!!"
               | "?" ;

ArgList        = Expr { Sep Expr } ;

PrimaryExpr    = Literal | "~" | "@" | "$" | Ident
               | IfExpr | MatchExpr | TryExpr | LoopExpr
               | AsyncSpawn | ComptimeExpr | LabeledBlock
               | FuncExpr | DataBracket | MetaBracket | "(" Expr ")" ;

(* Условия if / else if / else и сопоставление match *)
IfExpr         = "?" "(" Expr ")" Block { "(" Expr ")" Block } [ Block ] ;
MatchExpr      = "?" "[" Expr "]" "{" { MatchArm Sep } "}" ;
MatchArm       = Pattern [ "(" Expr ")" ] Block ;
Pattern        = Literal | "~" | "_" | Ident | RangeExpr
               | [ TypeIdent ] ( "(" [ Pattern { Sep Pattern } ] ")" | DataBracket )
               | Pattern "|" Pattern ;

(* Блок try / catch / finally *)
TryExpr        = "!{" { Statement Sep } "}"
                 { "?!" ( "[" Pattern "]" | "(" Ident ")" ) Block }
                 [ "?>" Block ] ;

(* Циклы, корутины, блоки с метками и comptime *)
LoopExpr       = "@" [ "(" ( Ident "<-" Expr | Expr ) ")" ] Block ;
AsyncSpawn     = "~>{" { Statement Sep } "}" ;
ComptimeExpr   = "<{" { Statement Sep } "}>" ;
LabeledBlock   = "#" Ident ( LoopExpr | Block ) ;

(* Функции и скобки данных *)
FuncExpr       = [ GenericParams ] [ "(" [ ParamList ] ")" ] [ TypeTag ] Block ;
ParamList      = Param { Sep Param } ;
Param          = Ident [ TypeTag ] [ "=" Expr ] ;
Block          = "{" { Statement Sep } "}" ;

DataBracket    = "[" [ DataContent ] "]" ;
DataContent    = "%" [ Expr { Sep Expr } ]
               | ".." Expr { Sep StructField }
               | MapEntry { Sep MapEntry }
               | VariantList
               | StructField { Sep StructField }
               | Expr [ TypeTag ] [ ".." Expr ] { Sep Expr } ;

StructField    = Ident [ TypeTag ] [ "=" Expr ] ;
MapEntry       = Expr "=>" Expr ;
VariantList    = Variant { "|" Variant } ;
Variant        = TypeIdent [ "(" TypeList ")" | DataBracket ] ;

TypeTag        = "[" TypeSpec "]" ;
TypeSpec       = [ "~" | "%" ] TypeIdent [ GenericArgs ] [ ".." ] [ "?" ]
               | TypeSpec "=>" TypeSpec
               | "(" [ TypeList ] ")" TypeTag ;
GenericArgs    = "<" TypeList ">" ;
TypeList       = TypeSpec { Sep TypeSpec } ;

(* Импорт и FFI *)
MetaBracket    = "<" StringLit [ StringLit "(" [ TypeList ] ")" TypeTag ] ">" ;

(* Базовые лексемы *)
Ident          = ( "a".."z" | "_" ) { "a".."z" | "A".."Z" | "0".."9" | "_" } ;
TypeIdent      = ( "A".."Z" ) { "a".."z" | "A".."Z" | "0".."9" }
               | "i8"|"i16"|"i32"|"i64"|"u8"|"u16"|"u32"|"u64"|"usz"|"f32"|"f64"|"bool"|"str"|"char" ;
Literal        = NumberLit | StringLit | CharLit | "1b" | "0b" ;

11. Пример реальной программы со всеми механизмами
Ниже показан полный код сервиса обработки заказов, использующий null-безопасность, if / else if / else, try / catch / finally, defer, методы, словари и асинхронность:
http = <"std/http">
log  = <"std/log">

# 1. Типы данных и ошибок
DbErr   = [code = 500, msg = ""]
Order   = [id = 0, item = "", qty = 1, coupon [str?] = ~]
Receipt = [order_id = 0, total = 0.0, status = ""]

# 2. Таблица цен, вычисляемая на этапе компиляции (comptime)
base_prices = <{
  ["laptop" => 1200.0, "mouse" => 25.0, "keyboard" => 80.0]
}>

# 3. Метод расчета скидки с проверкой null и цепочкой if / else if / else
Order.calc_discount = {
  # Безопасная цепочка ?. и Элвис ?? (если купона нет, код = "")
  code = @.coupon?.trim()?.upper() ?? ""

  ? (code == "VIP50") {
    0.50
  } (code == "SALE20" & @.qty >= 2) {
    0.20
  } (@.qty >= 10) {
    0.10
  } {
    0.0
  }
}

# 4. Обработка заказа с защитой ресурсов (defer) и try / catch / finally
process_order = (raw_order [Order?]) [Receipt?] {
  # Null-guard: если заказ пустой (~), мгновенно возвращаем ~
  order = raw_order ?? ^ ~

  # Безопасный поиск цены в словаре
  unit_price = base_prices[order.item] ?? ^ ~

  tx = db.begin_transaction()
  ~{ tx.close() }                             # defer: закроет соединение при любом выходе
  ?!{ tx.rollback() }                         # errdefer: откатит транзакцию при ошибке

  !{
    (order.qty <= 0) ?^ !^ DbErr[code = 400, msg = "Некорректное количество"]

    discount = order.calc_discount()
    final_sum = (unit_price * order.qty) * (1.0 - discount)

    tx.save(order.id, final_sum)?             # Проброс ошибки, если БД недоступна
    tx.commit()?

    Receipt[order_id = order.id, total = final_sum, status = "OK"]
  } ?! [DbErr[code = 400, msg = m]] {
    log.warn("Ошибка валидации заказа #{order.id}: {m}")
    Receipt[order_id = order.id, total = 0.0, status = "INVALID"]
  } ?! (err) {
    log.error("Критический сбой БД: {err}")
    ~
  } ?> {
    log.info("Завершена обработка заказа #{order.id}")
  }
}

# 5. Точка входа: асинхронный запуск и потоковая фильтрация
+main = {
  incoming [Order?..] = [
    Order[id = 1, item = "laptop", qty = 1, coupon = "vip50"]
    ~
    Order[id = 2, item = "mouse", qty = 3, coupon = ~]
    Order[id = 3, item = "unknown", qty = 1]
  ]

  # Параллельно обрабатываем все заказы, отбрасываем пустые (~) и печатаем чеки
  incoming
    ~>> { process_order(@) }
    ?~> { log.print("Чек #{@.order_id}: сумма {@.total} ({@.status})") }
}
